# Label composition and what histology adds over routine clinicopathological variables

Code and data description for reproducing:

> Ali Y, Gregori J. *Label composition explains whether histology outperforms
> routine clinicopathological variables: a controlled comparison of four breast
> cancer risk signatures.* Submitted to JCO Clinical Cancer Informatics, 2026.

Four recomputed genomic risk signatures (Oncotype DX recurrence score,
MammaPrint, PAM50 ROR-S and ROR-P) are predicted from H&E whole-slide images
in 82 TCGA-BRCA patients. Each slide is a fixed pool of 512 UNI patch
embeddings, pooled by gated-attention multiple-instance learning, trained under
one shared multi-label stratified five-fold partition and one configuration
fixed in advance. Every model is compared on identical folds, by paired
bootstrap, against ER status alone and against a six-variable
clinicopathological logistic model. The repository contains everything needed
to rerun that comparison from the patch embeddings onward, and describes how
the embeddings are obtained from the public slides.

This repository holds **code and input data only**. Model outputs, result
tables, figures and the manuscript are not tracked; they are regenerated by
the commands below.

## Data

All inputs are public and de-identified.

| What | Where it comes from | In this repository |
|---|---|---|
| Diagnostic H&E whole-slide images (90 slides, `*-01Z-00-DX1`) | NCI Genomic Data Commons, TCGA-BRCA | slide list in `data/tcga_brca/pool_manifest.jsonl` |
| Recomputed signature scores and group calls (100 patients) | Li et al, *Radiology* 281:382-391, 2016 (genefu recomputations from TCGA expression data) | `data/tcga_brca/Perou-TCGA-BRCA-metadata.csv` |
| Clinical and pathology variables | TCGA-BRCA clinical data, GDC | `data/tcga_brca/clinical_91_from_vincenzo.csv`, `data/tcga_brca/tcga_clinical_pathology_clean.csv` |
| 36 pre-extracted DCE-MRI radiomic features | Li et al 2016 (TCIA breast radiogenomics subset) | `data/tcga_brca/radiomics.csv` |
| UNI patch embeddings | computed from the slides (below) | **not tracked** (about 7 GB for the full Trident output; 360 MB for the 1,024-patch pools; 180 MB for the 512-patch pools) |

`data/tcga_brca/README.md` gives, for each file, the rows, the columns the
scripts read, and how the binary labels and the six clinical covariates are
derived from them.

### Patch embeddings

The embeddings were produced before this study as preparatory work in our
group and are not redistributed; they are regenerated from the public slides
in three steps.

1. **Segment, tile and encode** each slide with the
   [Trident](https://github.com/mahmoodlab/TRIDENT) toolkit (Zhang A et al,
   arXiv:2502.06750, 2025): tissue segmentation, non-overlapping 256-pixel
   tiles at 20x, encoder `uni_v1` (Chen RJ et al, *Nat Med* 30:850-862, 2024;
   weights require access approval on Hugging Face). Trident writes one HDF5
   file per slide with `features` (N x 1024, float32) and `coords` (N x 2).
2. **Reduce each slide once to a fixed pool.** A seeded per-slide random
   subset of 1,024 patches is taken from the Trident features and written as
   an `.npz` archive with keys `features`, `coords`, `source_n`, `kept`,
   `name`; the number of source patches and the number kept per slide are
   recorded in `data/tcga_brca/pool_manifest.jsonl` (median 19,376 source
   patches, range 3,334 to 32,498). This step runs without PyTorch
   (`scripts/extract_patch_pool.py`).
3. **Thin to 512 and convert to the training format** (`scripts/pool_npz_to_pt.py`):

   ```
   python scripts/pool_npz_to_pt.py --src data/tcga_brca/_pool --dst data/tcga_brca/_pool_pt --keep 512
   ```

   The 512 patches are drawn per slide with
   `numpy.random.default_rng((crc32("512" + slide_name) ^ 20260906) % 2**32)`,
   so the pool is a deterministic function of the slide name and the seed.
   Output is one `.pt` bundle per slide, `{"data": {"features", "coords"},
   "meta"}`, whose file name starts with the TCGA patient barcode
   (`TCGA-XX-XXXX`); that prefix is how bundles are matched to patients.

Both pool directories are ignored by git (`.gitignore`).

## Reproducing

Python 3.11. Install the pinned versions and the package:

```
python -m pip install -r requirements.txt
python -m pip install -e .
```

Then, from the repository root, with the 512-patch pools in
`data/tcga_brca/_pool_pt`:

```
# 1. Locked confirmatory run: shared partition, fixed configuration BB,
#    four targets, held-out predictions per fold.  ~25 min on 2 CPU cores.
python scripts/locked_rerun.py --pt_dir data/tcga_brca/_pool_pt \
    --out Results_locked/modal --fixed_grid BB

# 2. Pre-declared comparators on the same folds: ER alone and the six-variable
#    C = 1 logistic model; ER-positive / HER2-negative subgroups.
python scripts/locked_floor_comparison.py --results Results_locked/modal

# 3. Pre-extracted radiomic feature arm, nested vs non-nested CV on the same partition.
python scripts/radiomics_nested_cv.py --partition Results_locked/modal/shared_partition.csv \
    --out Results_locked/radiomics

# 4. Cohort table.
python scripts/make_table1.py --clinical data/tcga_brca/clinical_91_from_vincenzo.csv \
    --partition Results_locked/modal/shared_partition.csv --out Results_locked/modal

# 5. Tuned comparator, incremental value (stacked model, likelihood-ratio test),
#    alternative binarisation cuts, minimum detectable difference.
python scripts/review_response_analyses.py --results Results_locked/modal \
    --clinical data/tcga_brca/clinical_91_from_vincenzo.csv \
    --perou data/tcga_brca/Perou-TCGA-BRCA-metadata.csv

# 6. Repeated cross-validation: the whole locked pipeline under five
#    independently drawn partitions (repeat 0 is the locked seed).  ~1.8 h on CPU;
#    checkpoints per fold and resumes if interrupted.
python scripts/repeated_cv.py --pt_dir data/tcga_brca/_pool_pt --out Results_repeatedcv \
    --clinical data/tcga_brca/clinical_91_from_vincenzo.csv --repeats 5

# 7. Figures (design diagram, cohort flow, gain forest plot).
python scripts/make_submission_figures.py --results Results_locked/modal --out figs
```

Steps 2 to 5 and 7 run in seconds to minutes on CPU.

### What to expect

Step 1 writes, per target, `test_predictions.csv` (one row per patient:
`CLID, outer_fold, true, pred, binary`), `outer_folds.csv` and
`inner_selection.csv`, plus `shared_partition.csv`, `partition_balance.csv`
and `run_manifest.json` (seed, configuration, package versions). The
partition is drawn with seed 20260906 and should have 16, 18, 15, 17 and 16
patients in folds 0 to 4.

Step 5 writes `Results_locked/modal/review/comparators.csv`, which carries the
primary endpoint (pooled held-out AUC with 4,000-resample percentile CIs;
paired-bootstrap differences against each comparator). The reported values are:

| Target | AUC histology (95% CI) | ER alone | Clinical model (C = 1) | Gain over clinical model (95% CI) |
|---|---|---|---|---|
| Oncotype (GHI-RS) | 0.744 (0.631-0.846) | 0.582 | 0.464 | +0.280 (0.133 to 0.435) |
| PAM50 ROR-P | 0.815 (0.718-0.900) | 0.610 | 0.655 | +0.160 (0.012 to 0.300) |
| PAM50 ROR-S | 0.834 (0.727-0.921) | 0.672 | 0.710 | +0.124 (0.013 to 0.246) |
| MammaPrint (NKI70) | 0.892 (0.770-0.980) | 0.850 | 0.934 | -0.042 (-0.134 to 0.034) |

(n = 81; one patient with uninformative HER2 testing is excluded from the
comparator analyses.) Step 6 writes `Results_repeatedcv/summary.csv`; the
margin over the clinical model was positive in 5 of 5 partition draws for
Oncotype (+0.213 +/- 0.051), ROR-P (+0.199 +/- 0.045) and ROR-S
(+0.111 +/- 0.046), and in 2 of 5 for MammaPrint (-0.006 +/- 0.048).

### Determinism

The per-slide patch pool is fixed, the partition and inner splits are drawn
from a recorded seed, and all bootstrap procedures are seeded, so a rerun with
the pinned package versions reproduces the reported numbers exactly (repeat 0
of step 6 reproduces step 1 exactly and serves as a check on the harness).
Training on a GPU, or with different PyTorch or scikit-learn versions, may
change the model predictions in the third decimal; the analyses from the
predictions onward are bit-reproducible.

The "provisional" (before-locking) numbers quoted in the manuscript's design
comparison come from the earlier per-target development pipelines in our
group's codebase and are not regenerated here; everything reported as a
result of this study is.

### Notes on the code

`REFACTOR_NUMERICS.md` documents the numerical decisions behind the package
and refers to the unit tests of our group's development codebase, which are
not shipped here. Behaviours of the original development code that are
reproduced verbatim are marked `BUG-PRESERVED` in the source with a pointer
to that file; they are part of the reported pipeline and must not be
